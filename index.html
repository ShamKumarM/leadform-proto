WhatsApp Sales Assistant — Contact

Standalone prototype for the Create Contact and Update Contact flows. Contacts sync to NetSuite as the single source of truth.

Flow 1 — Create Contact

Standalone contact creation. Two capture modes:

  • Scan Visiting Card (OCR): User sends a photo; OCR extracts name, company, designation, phone, email and address (Address 1, Address 2, city, state, pincode). User confirms, edits or rescans.
  • Fill Manually: User fills the contact form directly.

After creation, user can promote to a lead or return to main menu. The new contact is added to the top of the user's recent contacts.

Flow 2 — Update Contact

Bot shows the 9 most recent contacts created by the user (sorted by last modified) with a Search field. Two paths:

  • 2A — Select from Recent: User taps a contact → bot shows the last saved details → Edit Contact opens the same form used for Create, pre-filled → Save Changes → bot confirms “Contact updated successfully” with a field-level change summary.
  • 2B — Search: User picks one search parameter — Name, Phone Number or Company → bot prompts for the value → user types and sends → bot lists matching contacts → user selects a contact → continues as 2A. User can run a new search, change search type or cancel at any point.

Key Principles

  • NetSuite is the single source of truth — all dropdown values from NetSuite master data, no inline creation
  • Contact must be linked to every lead; lead is optional for opportunities via existing customer path
  • Every submission syncs to NetSuite in real time

Update Contact

RuleDescription
UPD-01Recent list shows the 9 latest contacts created by the logged-in user, sorted by last modified.
UPD-02Selecting a contact always shows the last saved values from NetSuite before editing.
UPD-03Update uses the same form and validations as Create Contact.
UPD-04Save is blocked when no field has changed; the user is told “No changes detected”.
UPD-05On save, the contact's last modified time is refreshed and it moves to the top of the recent list.
UPD-06Success message lists each changed field (old → new) and confirms NetSuite sync.
UPD-07Cancel / ✕ discards unsaved edits; nothing is written to NetSuite.

Search

RuleDescription
SRCH-01User selects exactly one parameter per search: Name, Phone Number or Company.
SRCH-02Bot accepts typed input only after a parameter is chosen; other free text returns the options menu.
SRCH-03Invalid input (too short, letters in a phone number) is rejected with a hint; the bot keeps waiting for a valid value.
SRCH-04Results show up to 10 matches with the matched text highlighted; the user is asked to refine if there are more.
SRCH-05No match → Try Again, Change Search Type or Back to Recent Contacts.
SRCH-06User can start a new search from results at any time; the previous results stay reachable through “Back to Search Results”.

Validation

RuleDescription
VAL-01First Name and Phone 1 are mandatory.
VAL-02Phone numbers must have 10–13 digits; Phone 2 cannot equal Phone 1.
VAL-03Phone 1 is the dedupe key — it cannot match another contact's number.
VAL-04Emails must be valid; Email 2 cannot equal Email 1.
CITY-01City dropdown lists 19 major cities, with “Others” as the 20th item.
CITY-02Selecting “Others” shows a mandatory City Name text field below the dropdown.
CITY-03On update, a saved city that is not in the list opens with “Others” selected and the city pre-filled.
ADDR-01Address 1, Address 2, Pincode, City and State are all optional.
ADDR-02Pincode, when entered, must be 6 digits and cannot start with 0.
ADDR-03A pincode found in the master auto-fills City and State; both stay editable. Unknown pincodes leave them for manual selection.
